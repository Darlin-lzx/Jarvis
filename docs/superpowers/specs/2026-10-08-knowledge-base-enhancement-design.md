# 知识库能力增强设计

## 目标

按照《数据库国产化迁移智能编排平台详细设计文档 v2.0》第 6 章优化现有知识库：建立“业务域 × 知识类型”分类、统一检索接口、混合召回与融合排序、可信度门禁、命中溯源和负反馈闭环。改造保持渐进兼容，不重建存量向量索引，不改变现有状态机和 Agent 编排。

## 范围

- `kb_documents` 增加业务域、目标库、阶段、对象类型、可信度、来源、时效和负反馈字段。
- RAG 元数据同步这些字段；旧数据默认映射到 `db_migrate` 业务域。
- `RAGStore` 检索扩大候选到 Top20，执行 0.35 相似度阈值、域匹配度和可信度融合排序。
- 新增 `POST /api/knowledge/search` 供 Agent 与调试面板使用，保留 `/api/kb/search` 兼容旧前端。
- 新增 `POST /api/knowledge/feedback` 支持负反馈降权与待审标记。
- 前端知识库管理页支持业务域 / 知识类型筛选、结构化检索参数、综合分与相似度展示、可信度提示和负反馈操作。

## 非目标

- 不在本任务实现完整插件注册、热加载和通用 Task State。
- 不引入新向量数据库，不强制迁移或重建现有 FAISS 索引。
- 不实现人工修正 SQL 自动沉淀规则，仅预留字段与反馈入口。

## 设计

### 分类模型

业务域默认 `db_migrate`，后续插件可注册其他业务域。知识类型沿用并扩展现有 `kb_type`：`rules` 规则库、`cases` 案例库、`risks` 风险库、`templates` 模板库、`doc` 归档文档、`ops` 运维手册。上传时由前端选择，未选择的旧数据保持原值。

### 检索流程

1. 按业务域、空间、知识类型、目标库、阶段和对象类型过滤。
2. 语义召回 Top20 候选。
3. 丢弃余弦相似度低于 0.35 的候选。
4. 计算综合分：`0.4 * domain_match + 0.3 * confidence + 0.3 * similarity`。
5. 返回 Top3-5，并附可信度、来源、是否需人工复核、精确匹配或语义召回标记。

### 可信度

`verified` 与 `human_authority` 为 1.0，`pending_review` 为 0.6，`model_generated` 为 0.4。负反馈将可信度下调一级并设置待审核标记。

### 降级

向量服务失败或超时返回空结果，不阻断对话。检索无命中时返回明确的 `no_hit` 元信息，供后续提示“无知识命中，需人工关注”。

## 验收

- 存量文档可以继续列出、检索和删除。
- 新上传文档可以指定两级分类和结构化标签。
- 检索结果包含相似度、综合分、可信度和溯源信息。
- 低可信度结果带需人工复核标记。
- 负反馈会降低文档可信度并触发待审核。
- 后端 RAG/API 测试、前端测试和 TypeScript 检查通过。
